# Hanvi Web

The browser frontend: the core compiled to WebAssembly, running in a Web Worker, behind a React + TypeScript UI built with Vite.

```
web/
├── wasm/             embind bindings over the core (C++, built by CMake)
└── src/
    ├── core/
    │   ├── worker.ts     loads the module and data, exposes the API with Comlink
    │   ├── client.ts     `core` proxy the UI awaits (`await core.convert(text)`)
    │   ├── types.ts      shapes returned by the bindings
    │   └── generated/    hanvi.js / hanvi.wasm / hanvi.d.ts (build output, ignored)
    └── App.tsx
```

The module is single-threaded, so the page needs no cross-origin isolation headers; it runs in a worker so loading and long conversions don't block the UI.

## Building

Prerequisites: [emsdk](https://emscripten.org/docs/getting_started/downloads.html), Node.js, and a native build of the repository (the OpenCC `.ocd2` dictionaries are generated by host tools, which can't run when cross-compiling).

1. Once per emsdk install, give Emscripten its own TypeScript compiler (used for `hanvi.d.ts`):

   ```sh
   (cd "$EMSDK/upstream/emscripten" && npm ci)
   ```

2. Build the module. It is written to `src/core/generated/`, and `dict.db` plus the OpenCC data are copied to `public/data/`:

   ```sh
   source "$EMSDK/emsdk_env.sh"
   emcmake cmake -S .. -B ../cmake-build-wasm -DCMAKE_BUILD_TYPE=Release \
       -DHANVI_OPENCC_DATA_DIR=<native build>/opencc
   cmake --build ../cmake-build-wasm --target HanviWasm
   ```

3. Run the app:

   ```sh
   npm install
   npm run dev       # or: npm run build && npm run preview
   ```

Rebuild the module (step 2) after changing the core or the bindings; Vite reloads it.

## Notes

- `dict.db` is about 40 MB (roughly 10 MB compressed); serve `public/data` with compression.
- Edits are not persisted yet. The plan is to keep the database in OPFS/IndexedDB using the core's `save_db_copy()` / `db_change_count()`, with import and export of `dict.db`.
